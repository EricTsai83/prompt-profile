Improve your prompts

From your own prompts; each suggestion cites what it is based on

1

Save your standing defaults once

You retype the same rules in session after session: reply in Chinese, commit by scope on main, delete test recordings, push and watch CI.

Language corrections like "用中文回我。" come up again and again, the language rule once flipped to "應該要英文回覆我。", and promptHabits shows 9 reused openings across 79 sessions.

Write these defaults into AGENTS.md/CLAUDE.md or the implement skill, including the reply language. Then a short trigger like "照預設流程收尾" is enough.

You wrote
直接幫我根據 scope 在 main branch 做 commit 就可以了。 然後測試錄影幫我刪掉。
Try

照 AGENTS.md 的收尾流程做（依 scope 分批 commit 到 main、刪除測試錄影）。

2 quotes as evidence
  • 用中文回我。
  • 應該要英文回覆我。
2

Give visual targets up front

Visual and animation requests start with words like "好看又流暢" or "更有活力", and the real constraints only show up across several corrections.

The color direction went from more vibrant to single tone to black/white with red, and the glow-overlap constraint only came out after the first animation attempt.

In the first ask, name the element, the motion or palette constraints, and a reference. Then ask for several versions to pick from, which you already like doing.

Try

幫我將 Ready in 5 step 那邊設計流暢的動畫：光暈不能跟 icon 重疊，風格要符合 Mac。請先做多個版本讓我挑選。

2 quotes as evidence
  • 並沒有，我現在還是可以看到光暈會跟 icon 重疊，但這不是我要的效果。
  • 整個設計顏色太多了。我希望還是以單一色調為主
3

Add step, expected and observed

Bug and test reports are often a bare screenshot or a one-liner, and context such as the URL arrives in a later turn.

The AI has to guess which step or feature you mean. In one production bug, the URL only came in a follow-up message.

Include where it happened, what you did, what you expected and what you saw. Even one line of each is enough.

You wrote
在 production 的環境遇到這個問題。
Try

在 production（https://draw.ericts.com）遇到截圖中的問題。操作步驟：___；預期：___；實際：如截圖。

2 quotes as evidence
  • https://draw.ericts.com網址是這個。
  • 中斷連線後似乎就接不回了
4

One action per message

Single prompts often bundle a commit, a bug fix and an open design question together.

Action items and discussion get mixed together, so it's easy for one request, such as the icon bug next to a code review, to get a thinner answer or be dropped.

Number separate asks, or send the discussion question after the action is done.
