# 03 · Claude Code adapter

Status: implemented; later extended with technique metadata (plan 17). Acceptance checked 2026-10-24.

## Goal

From the user's local Claude Code data, read **the prompts the user actually typed themselves** and output a `Stream<PromptRecord>`.

## Data location and format (verified against real data, 2026-10, Claude Code 2.1.x)

Root directory: `$CLAUDE_CONFIG_DIR`, or `~/.claude` if unset.

### 1. `projects/<encoded project path>/<sessionId>.jsonl` (primary source)

Each line is an event. Only lines with `type === "user"` matter:

```jsonc
{
  "type": "user",
  "uuid": "…", "parentUuid": "…" | null,
  "sessionId": "…", "timestamp": "2026-…Z",
  "cwd": "/Users/…/project", "gitBranch": "main", "version": "2.1.309",
  "isSidechain": false,
  "entrypoint": "cli" | "sdk-ts" | "sdk-cli",
  "promptSource": "system" | "sdk" | undefined,
  "turnOrigin": "task_notification" | "sdk" | "scheduled" | "peer" | undefined,
  "message": { "role": "user", "content": "string" | [ { "type": "text" | "tool_result" | "image", … } ] }
}
```

All other `type`s (`assistant`, `attachment`, `api-request`, `ai-title`, `mode`, `queue-operation`…) are skipped.

### 2. `history.jsonl` (supplementary source)

```jsonc
{ "display": "prompt text", "pastedContents": {}, "timestamp": 1774954817129, "project": "/Users/…", "sessionId": "…" }
```

Contains only interactive CLI input. Used to recover old sessions that have already been deleted from `projects/` (Claude Code deletes session files older than 30 days by default).

Note: `display` is not the original text. Long pasted text becomes `[Pasted text #1 +42 lines]` with the original in `pastedContents`; slash commands (`/clear`, `/model`…) also appear here.

## Filter rules (what the user did not write themselves)

In real data there are about 3,600 records with `type: user` and string content, of which **only about 1/3 were actually written by a human**. Exclude:

| Exclusion condition | Reason |
|---|---|
| `isSidechain === true` | Subagent-internal conversation |
| `promptSource === "system"` or `turnOrigin === "task_notification"` | Notifications sent automatically by the system |
| content starts with `<task-notification>`, `<local-command-caveat>`, `<local-command-stdout>`, `<command-name>`, `<system-reminder>` | Content generated by tools or the system |
| content is an array containing only `tool_result` | Tool results, not prompts |
| text contains the `[prompt-profile:analysis]` marker | **Analysis prompts we sent ourselves** (see plan 06), so we never analyze ourselves |

Keep:
- String content, or the `type: "text"` parts of an array (multiple text parts joined with newlines).
- A `type: "image"` part in the array → `hasImage: true`.
- `origin`: `entrypoint === "cli"` → `interactive`; `sdk-*` → `sdk`; anything else → `unknown`. `client` stores the raw `entrypoint` value.
- **`sdk` sources must be kept**: people who use Claude through desktop apps such as T3 Code or Conductor have all their hand-typed prompts recorded as `entrypoint: "sdk-ts"`. But those apps also let the AI spawn subtasks (e.g. child threads created by an orchestrator), and those prompts are written by the AI. The MVP does not decide this in the adapter; plan 05's filter rules handle it, and the adapter only has to fill in `origin` and `client` correctly.
- Slash commands like `<command-name>/xxx</command-name>` are not treated as prompts, but **the command name is recorded** for stats (e.g. the most-used slash commands). This can be emitted outside PromptRecord for now, or deferred; explain the choice in the PR.

## Merging and dedup

- **Dedup per session**: in `history.jsonl`, records whose `sessionId` already has a matching `projects/**/<sessionId>.jsonl` are **skipped entirely** (no text comparison, because `display` replaces pasted content with placeholders, so text matching would always fail).
- Only sessions not found in `projects/` are recovered from `history.jsonl`. When recovering:
  - Skip records starting with `/` (slash commands), but count the command name in the slash command stats.
  - When `pastedContents` has content, replace `[Pasted text #N …]` with the original text (plan 05 later folds overly long pasted content).
  - `origin: "interactive"`, `client: "history"`, `gitBranch: null`.
- Within one `projects/` file, keep only one record per `uuid` (resume / fork may write duplicates). The same `uuid` appearing in different files is also kept only once.
- `PromptRecord.id`: `claude-code:${sessionId}:${uuid}`; records from `history.jsonl` use `claude-code:${sessionId}:h${timestamp}`.

## Implementation requirements

- Lives in `src/adapters/claude-code/`, implements plan 02's `SourceAdapter` interface, and is registered in `src/adapters/registry.ts`.
- Shared line-by-line JSONL reading goes in `src/adapters/common/jsonl.ts`: read line by line with FileSystem + Stream; **a line that fails to parse is only counted and skipped** and must never fail the whole flow (do not print a warning per line; `diagnostics` reports everything at the end).
- Tolerate "files currently being written": the last line may be incomplete; treat it as a bad line and skip it.
- Filter rules (exclusion conditions, injected-content prefixes) are written as data arrays; each rule has a name, and `diagnostics` reports exclusion counts by name.
- Define a "lenient" input format with Effect Schema: declare only the fields used, ignore other fields, and let unknown `type`s pass. Claude Code changes very frequently.
- A missing directory returns an empty Stream, not an error.

## Tests

- `test/fixtures/claude-code/`: hand-written fake session files covering every filter rule above, plus one broken JSON line.
- Tests: one case per filter rule (table-driven), session-level dedup, `pastedContents` restoration, slash commands, duplicate `uuid`, bad lines skipped, missing directory, `CLAUDE_CONFIG_DIR` override.
- Snapshot: the parsed output of the whole fixture directory.
- `test/smoke/claude-code.test.ts`: reads the real `~/.claude`, skips if not found; only checks "runs to completion, count > 0, every record passes the Schema". **Never print real content or write it into a snapshot.**

## Acceptance criteria

- [x] All tests pass; the smoke test reads a record count locally and prints how many records each filter rule excluded
- [x] Parsing all of the user's local data completes within 5 seconds (`test/smoke/claude-code.test.ts`; it can exceed this when the machine is busy)
